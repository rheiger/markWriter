# SQL highlighting benchmark

Run `npm ci --prefix frontend`, then `npm run dev --prefix frontend -- --port 5180` with Node 24+. Open `http://127.0.0.1:5180/benchmarks/sql-highlight.html` in a local browser and copy the JSON from the page. The page uses synthetic SQL, invokes the real CodeMirror and Tiptap extensions, and measures 20 synchronous editor dispatches and 20 separate mapped Preview renders including `innerHTML`. It reports all samples, initial creation, text sizes and visible token counts; record the browser, machine, and cold and warm results. It deliberately isolates editor/Preview work, so it is not a measurement of a complete app interaction, installed WebKit, frame presentation, native save, or Finder. Repeat on the baseline and candidate on the same idle machine. SQL over the baseline cap is expected to be literal there, so compare outcomes as well as time.

The SQL policy counts UTF-16 units: one 131,072-unit SQL block and 131,072 aggregate SQL units per render/rebuild, 2,048 units per line, and 24,576 styled ranges per block. Other language budgets remain separate. Over-budget input is preserved as literal text. Quick Look has separate limits and a native deadline. UTF-8 byte size depends on content; these are not byte limits. Preview updates after edits to documents over 4,096 units are coalesced for 100 ms, and guarded by owning document and revision. The benchmark measures render time independently; it does not measure the debounce or prove the complete UI-thread budget.
