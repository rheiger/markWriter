# Quick Look feasibility checkpoint — 7 November 2026

**Gate: not passed.** The isolated unsigned prototype did not compile because Xcode 27.2 reported that its license agreements had not been accepted. No executable was produced and no provider was installed or registered. We therefore have no evidence that Finder discovers or selects MarkWriter for Markdown, JSON, XML, YAML, or JSONL, or that a preview renders. This is a toolchain gate, not evidence that a signature is required for this particular test. Do not ship or claim #48/#49 from this prototype.

## What was examined

The local Mac reports macOS 27.2 (26B123), Xcode 27.2 (27B52). Read-only `qlmanage -m plugins` reports the system `Text.qlgenerator` against `public.json` and `public.xml`, so these formats already have providers. This listing is not a controlled test of which provider Finder selects and does not establish Markdown/YAML/JSONL resolution. `pluginkit -m -p com.apple.quicklook.preview` also reports existing Apple and third-party preview extensions; it does not prove their selection for these formats. Full output and host versions are in the run's `evidence/quicklook/` directory. No provider or default was modified.

Apple's [Quick Look UI documentation](https://developer.apple.com/documentation/quicklookui/) describes a separate preview extension. Its [data-based provider documentation](https://developer.apple.com/documentation/quicklookui/qlpreviewprovider) specifies a `QLPreviewProvider` conforming to `QLPreviewingController`, the data-based flag, supported UTIs and principal class. The installed Xcode Quick Look template identifies the extension point as `com.apple.quicklook.preview`. The SDK supports plain-text replies. Apple identifies Markdown as `net.daringfireball.markdown` in its [UTType documentation](https://developer.apple.com/documentation/uniformtypeidentifiers/uttypemarkdown).

There is a material policy and selection risk: Apple's [convenience guidance](https://developer.apple.com/documentation/technologyoverviews/convenience) says to create preview extensions only for custom formats one defines and notes that standard formats already have system previews. Markdown and these structured formats are common types, not MarkWriter-owned formats. Listing an existing UTI is not proof the OS will choose our provider. Keep the collision and platform policy questions explicit; do not manufacture proprietary UTIs for existing user documents merely to bypass provider selection.

The [older Apple extension guide](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/ExtensionCreation.html) describes embedding in a containing app, sandbox/read-only entitlements in OS X templates, and consistent ad-hoc or developer signing for testing; its historical guidance needs current-OS verification. The release's ad-hoc host seal alone does not establish extension eligibility. Trusted distribution and notarization require the separately scoped signing work; signing has not been authorized here. An actual target needs validated extension entitlements, bundle identity, nested embedding, build and packaging integration, and inside-out sealing appropriate to the chosen distribution path. None is yet qualified.

## Isolated prototype and result

`native/quicklook/PreviewProvider.swift` and `Info.plist` are a feasibility sketch only. The provider returns literal UTF-8 plain text, with a 1 MiB input limit and explicit fallback for oversized/non-UTF-8 input. It does not render Markdown or support diagrams, math, images, JSON formatting, JSONL, YAML or XML; it is not connected to the application, build, packaging, or registration. Its Info.plist syntax passes `plutil -lint`; that check does not validate a functioning extension. The source has not compiled and has not been reviewed or security-qualified.

An isolated attempt used `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, the run's `tmp` directory and `targets/quicklook` for output, with `swiftc -emit-library -application-extension -Xlinker -no_adhoc_codesign`. `xcrun` returned: “You have not agreed to the Xcode license agreements” and suggested `sudo xcodebuild -license`. No license was accepted and no sudo was run. `evidence/quicklook/build.log` records the output; `SHA256SUMS.txt` records prototype inputs and log. Xcode DerivedData was not used because the attempt invoked `swiftc`, not an Xcode project. No signing operation occurred.

The existing UTF-8 literal sketch is not a rendered preview.
