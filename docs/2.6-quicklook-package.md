# Quick Look package candidate for macOS

The 2.6 Quick Look packaging path puts the sandboxed preview extension in `MarkWriter.app/Contents/PlugIns` on Apple silicon. The extension declares Markdown, JSON, NDJSON, YAML and XML using their existing type identifiers. It reads a bounded display copy of the selected file. The ordinary package workflow checks the renderer and the unsigned bundle layout on macOS. A separate stage creates the Quick Look DMG only after the nested extension and app pass strict signature verification and the extension has the reviewed entitlements.

## Finder evidence

The signed prototype at source `0b32b88` was tested on macOS 27.2 (26B123), Apple silicon, with the editor closed and open. Both passes gave these results.

| Fixture | Finder selected the prototype | Output |
| --- | --- | --- |
| `.md` | Yes | Rendered heading, paragraph and fenced code |
| `.json` | Yes | Indented JSON with source token spelling preserved |
| `.ndjson` | Yes | Formatted records and a line number for the invalid record |
| `.yaml` | Yes | Literal fallback in the earlier prototype |
| `.xml` | Yes | Indented simple element tree |
| `.jsonl` | No | Finder file-info panel |

Finder logged XPC connections to the test extension. Removing the temporary PlugInKit and Launch Services entries restored the fallback previews on fresh copies. All 18 fixture hashes and timestamps and all 34 protected file hashes matched their baselines. The legacy MarkWrite app remained installed throughout. Its Markdown document role controls opening files and it contains no Quick Look extension.

The current renderer adds display formatting for YAML block mappings, lists and multiple documents. It keeps indentation and scalar spelling, supports plain Unicode values, and falls back for aliases, anchors, quoted values, flow collections, block scalars and other unsupported constructs. Limits are 1 MiB input, 5,000 lines, 128 spaces of indentation, 64-byte simple keys and 2 MiB of formatted text. The renderer makes no syntax validation claim for this YAML subset.

A scoped Launch Services probe imported Apple's `public.ndjson` with both `ndjson` and `jsonl` tags, without an editor claim. Fresh processes still resolved `.jsonl` to a dynamic identifier and `.ndjson` to `public.ndjson`. The registered public type still listed only `ndjson`. Removing the probe restored its registration baseline. The package omits the ineffective declaration and any dynamic identifier. Apple also advises limiting Quick Look extensions to app-defined formats, so the common-type results here establish local behavior and leave distribution policy for review. [Type declarations](https://developer.apple.com/documentation/UniformTypeIdentifiers/defining-file-and-data-types-for-your-app) · [Quick Look guidance](https://developer.apple.com/documentation/technologyoverviews/convenience)

## Build and verify

Build the ordinary arm64 app with the locked frontend and Tauri toolchain, using `tauri build --bundles app`. Run the wrapper from the checkout and choose fresh absolute output paths.

```sh
tools/package-quicklook-macos.sh stage /path/to/MarkWriter.app /path/to/new/staging
# After separately authorized signing of the nested extension and outer app:
tools/package-quicklook-macos.sh dmg /path/to/staging /path/to/MarkWriter-2.6.0-QuickLook.dmg
```

The nested extension uses `native/quicklook/Preview.entitlements`. An ad hoc test must sign the nested code first and the host last. The DMG wrapper refuses the unsigned stage. A signed image must be mounted read-only and copied to an isolated installation directory. Verify the app and extension signatures there, and verify Finder Space with the editor closed and open. Compare fixture hashes and timestamps, then remove only the test registrations and repeat on fresh fixtures.

The table above qualifies the earlier prototype. The updated YAML renderer and unsigned package stage passed local checks. The rebuilt DMG and its installed Finder behavior await separate local signing approval.
