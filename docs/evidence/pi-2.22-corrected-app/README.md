# Installed Ubuntu and Windows package qualification

The candidate source is `ce882d781441c8376f69f52da5b27bf3f3a5f83e`. These research packages retain version 2.21.1. Both qualification workflows fetch an installer and manifest from the original producer, check the source and build run, verify the installer byte count and SHA-256, install it, and verify the installed executable SHA-256. The renderer is the pinned `@plantuml/core@1.2026.10` with bundled Smetana and a dedicated SVG validation worker. [Producer run](https://github.com/rheiger/markWriter/actions/runs/45878938169)

## Ubuntu desktop

A clean Ubuntu 26.04.1 LTS x64 runner installed the unsigned 10,130,394-byte DEB with dpkg. The installed binary ran under the ordinary runner account on Xvfb with WebKitGTK 2.52.6, a synthetic document, a fresh profile and a network namespace containing only loopback. The renderer and SVG validation workers returned HTTP 200 with the exact JavaScript bytes from the manifest and the expected worker CSP. [Ubuntu verification job](https://github.com/rheiger/markWriter/actions/runs/45879383738/job/140114546522) · [Installer identity and executable hash](ubuntu/manifest-excerpt.json) · [Producer artifact](ubuntu/artifact.json)

WYSIWYG, read-only Preview and the HTML saved with File → Export as HTML and the GTK file dialog agreed on all measured SVG shapes, attributes and text. Each diagram had 20 measured elements. The sequence included Alice, Bob, Request, Response and two arrowheads. The class diagram included User, Order, integer fields, the owns link and its 1 and * ends. The missing theme retained its readable source. The original Markdown matched its initial bytes. Independent inspection of the downloaded 7,669-byte export verified the SVG labels, fallback, ordinary hyperlink and absence of script, image, iframe, link, object and embed elements. [Raw receipt](ubuntu/result.json) · [Saved HTML](ubuntu/synthetic-export.html)

A fresh session took 4,030 ms through the first completed WYSIWYG render, including session startup and both worker checks. Switching to Preview took 1,020 ms. Across 36 process-tree samples, the maximum aggregate RSS was 943,852 KiB with up to nine processes. Host filesystem caches were uncontrolled. The sampler can count shared pages multiple times and miss peaks between samples.

## Windows desktop

Windows Server 2025 Datacenter build 26100 installed the unsigned 8,073,981-byte x64 NSIS package into Program Files. The app ran at medium integrity using WebView2 157.0.4341.46 with a separate profile. Scoped outbound firewall rules covered the application and its WebView runtime, with loopback available to the driver. Both worker responses matched the asset SHA-256 and expected restrictive CSP. The installed WebView also fetched `/THIRD_PARTY_NOTICES.txt` and received HTTP 200, `text/plain`, 5,084,463 bytes and SHA-256 `2078cf4c5242dcf56eb16b9eef81a207513e7e09ff34272ea11f2dbcfd282089`, matching the source file and the producer manifest. [Windows verification job](https://github.com/rheiger/markWriter/actions/runs/45879466032/job/140114822726) · [Installation receipt](windows/pi222-installed.json) · [Producer artifact](windows/pi222-artifact.json)

WYSIWYG, read-only Preview and the native File → Export as HTML command each produced sequence and class SVGs and preserved source for the missing theme, malformed class and valid fifth block beyond the four-block budget. The original Markdown retained its SHA-256. Independent inspection of the downloaded 7,705-byte export verified actor, participant, request, classes, relationship label and ends, all three source blocks, the ordinary hyperlink, and absence of active elements and external CSS resources. Opening the synthetic document through the Windows file dialog took 9,459 ms through first render. Switching to Preview took 1,069 ms. Native HTML export including its Save dialog took 2,727 ms. One post-preview sample summed 489,205,760 working-set bytes across seven observed application and WebView processes. A single sample cannot establish a peak. The Windows fixture and timing boundaries differ from Ubuntu.

## Reproduction and scope

The Ubuntu qualification used harness revision `022a9c9a43ed00271190ad03bbab8599123549a1`. The Windows qualification used `62ffe8c`. Both workflows hard-code the producer run and candidate SHA. The archived artifact receipts identify the producer package by GitHub artifact ID and digest. The harnesses run the installed GUI using synthetic documents. Controlled Finder timeout and recovery, Mac Preview and release-version installation belong to separate gates.
