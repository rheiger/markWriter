MarkWriter 2.1.0-alpha3 is an experimental prerelease for technical writing with Markdown, code and diagrams. It keeps the existing stable/latest release unchanged.

- Theme-consistent toolbar and explicit View→Theme Auto/Light/Dark choices synchronized with Settings, including live Auto appearance updates for editor/diagram themes.
- Shared ordinary-code syntax highlighting in Markdown source, WYSIWYG and Preview, with local token CSS in self-contained HTML export. The original language set is extended with CSS, Swift and Makefile: 19 variants, with Zsh using the Bash grammar and `m` recognized for Objective-C. Explicit language/alias wins; View and toolbar share a saved default-on toggle. Canonical Markdown, Undo, folds, selection and independent fonts remain view-independent.
- Literal input protection in fenced code, inline code and blockquotes, retaining intentional Unicode and composition. Automatic replacement guards also cover queued replacements targeting technical text after the caret moves.
- An illustrated paper-and-brass-nib icon across native packages and About, with expanded product and open-source credits and the exact Richie attribution.
- Fixes for cross-mode Undo, stale clipboard completion, menu completion ownership, viewport-clamped table picker growth and bounded Windows atomic preference replacement retries.

The packages target Apple Silicon macOS, Windows x64 and Ubuntu 26.04 x64. macOS has a strictly verified whole-bundle ad-hoc seal, providing integrity rather than Developer ID trust or notarization. Windows remains unsigned. No browser-quarantine or broader OS icon-cache/upgrade visual acceptance is claimed. Keep OS protections enabled and consult the [installation, profiles and rollback guide](https://github.com/rheiger/markWriter/blob/v2.1.0-alpha3/docs/install-alpha3.md).

Code presentation bounds: 4 Ki UTF-16 units per explicit block, 2 Ki per automatic block/line; 16 Ki/64 blocks/4 automatic attempts per document rebuild. Excess stays plain with all source retained. These are work/input limits, not a hard CPU deadline. Practical unlabeled detection is limited; broader detection and Java/Perl/AWK/sed/CMake are deferred to [#44](https://github.com/rheiger/markWriter/issues/44). Prefer explicit fence languages.

Genuine WYSIWYG edits use the existing Markdown serializer, which can normalize formatting and collapses repeated spaces in inline code ([#46](https://github.com/rheiger/markWriter/issues/46)). Use source editing when exact whitespace matters. Native smart-punctuation prevention is tested on the recorded Mac baseline; active spelling-service and arbitrary text-expansion configurations are not individually qualified. View-only changes preserve exact source. Read the [feedback acceptance and limits](https://github.com/rheiger/markWriter/blob/v2.1.0-alpha3/docs/alpha3-feedback-acceptance.md) and the attached release qualification/manifests for exact source, tested baselines and checksums.

PDF #41, DBML #33 → SQL DDL #42, PlantUML #31, expanded Help #47, native Quick View #48/#49 and other backlog remain deferred. Historical releases/tags remain unchanged. No stable/latest promotion or automatic updater is included.
