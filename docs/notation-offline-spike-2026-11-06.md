## Assets and policy observations

- Npm pins/lock integrity are in the isolated spike project. Viz package metadata says MIT and 4,994,623 unpacked bytes; DBML says Apache-2.0 and 36,865,577 unpacked bytes. Complete transitive runtime attribution remains a separate shipment gate. Neither package entered root/frontend production manifests/locks.
- PlantUML jar is 30,020,557bytes; downloaded from [official release 1.2026.9](https://github.com/plantuml/plantuml/releases/tag/v1.2026.9), SHA256 `aa4a1d06f8911c4b842beff4828dd955be431692b631a312d04c0e9fab9581de`, equal to GitHub's release-asset digest. The host JDK is 373 MiB; that is an observation about the spike machine, not a proposed product footprint. [Upstream download/licensing options](https://plantuml.com/download).
- MarkWriter's document meta CSP has `script-src 'self' 'unsafe-inline'`; Tauri configuration has `csp:null`. With only document meta policy, a static worker without a response policy runs Graphviz; the browser requested only local 127.0.0.1 resources. Applying the same CSP to the worker response produces `WebAssembly.instantiate()` compilation denial. That distinction prevents mistaking an ungoverned worker for a policy-compliant one. A future narrowly scoped worker/WASM policy must be evaluated explicitly; general `unsafe-eval` was not enabled.
- Hostile DOT retained `javascript:alert(1)` in its raw SVG anchor. An external image fixture returned virtual-filesystem warnings. This does not establish universal filesystem/network rejection; attribute/resource validation and output sanitization remain mandatory.
- PlantUML SANDBOX rejected the generated local include; malformed/environment fixtures returned error SVG, so checking only for `<svg>` would incorrectly accept errors. Exit status/error detection is required. Source was not uploaded to a renderer and no server/runtime download occurs during rendering. Dependency/jar acquisition was an explicit development step.

The worker cancellation measurement demonstrates a killable isolated layout experiment, not a complete bounded application renderer. Input/output/time limits, worker/process ownership and stale-result cancellation must exist in any future product adapter, together with the full fence/node/fold/search/navigation/persistence/export slice. Existing Mermaid remains the only integrated diagram notation.

## Reproduce the isolated experiments

Copy `docs/spikes/notation-2.1/` to a generated temporary directory; do not install these dependencies into the application. Run `npm ci --ignore-scripts`, acquire the pinned official jar and verify the hash, then `node spike.mjs` and `node cancellation.mjs`. Java is an explicit spike prerequisite; this is not a supported user installation requirement.

For browser checks, bundle `browser-dbml.js` using `npx --yes esbuild@0.25.12 browser-dbml.js --bundle --platform=browser --format=esm --outfile=browser-dbml-bundle.js`, then `node server.mjs /absolute/path/to/markWriter`. Inspect `http://127.0.0.1:8106/` and `window.dotResult` / `window.dbmlResult`. `server.mjs` applies the current policy to worker responses; removing only that response header reproduces the ungoverned-worker comparison. Expected CSP errors belong to this isolated failed-gate experiment, not accepted core application flows. Stop this temporary server after inspection.
