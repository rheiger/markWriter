# SQL DDL import preview

Open **Insert → Diagram → Import SQL DDL…**. On macOS, **Import SQL DDL…** is directly in the native **Insert** menu. Choose the dialect that produced the schema, then select a regular local UTF-8 `.sql` file up to 64 KiB (65,536 bytes including an optional UTF-8 BOM). A Markdown file, or Markdown fences wrapped around SQL, is not an import file. If the encoding is rejected, save a copy as UTF-8 and select that copy. Review or edit the generated DBML and choose **Append DBML**. MarkWriter checks that it can render the edited DBML before adding one fenced block at the end of the current document. One Undo removes the import. The source file is not changed; conversion, diagram and HTML export stay local.

The preview supports a subset of schema DDL, including ordinary tables, primary and unique keys, explicit foreign keys and composite keys. PostgreSQL also accepts supported `ALTER TABLE … ADD` constraints. Unqualified PostgreSQL names use `public`. SQLite uses its `main` schema.

Review keys, optionality and cardinality against the original. Diagrams omit accepted defaults and foreign-key actions. SQLite affinity and differing PostgreSQL types can make an apparently unique foreign key match more than one child, so the importer warns and shows a conservative many-to-one relationship in those cases. You can edit the DBML to reflect facts about your schema that the importer cannot infer.

Unsupported statements stop the import and leave the document untouched. Examples include SQLite `PRAGMA`, `AUTOINCREMENT`, views, row data, triggers, indexes, `CHECK` constraints, implicit foreign-key targets, serial or identity columns, and SQLite table options such as `STRICT`. Errors identify a line when available. Choose the matching dialect and use a separate schema excerpt containing supported DDL; do not remove constraints from your original schema. If edited DBML cannot render, it remains in the preview for correction and nothing is appended. Cancelling also leaves the destination untouched. Reopen import if the destination changes while the dialog is open. The importer is a diagramming aid and does not validate against a database server.

The 64 KiB SQL limit remains in place. Conversion also requires generated DBML to fit 32 KiB, 40 tables, 400 columns and 100 relationships, followed by the DOT and layout limits. A larger file cannot be qualified by SQL byte size alone; schemas with long names can exceed the DBML limit before rendering.

The [PostgreSQL retail migration](../tools/fixtures/sql-import/postgresql-retail.sql) and [SQLite workspace and notes schema](../tools/fixtures/sql-import/sqlite-notes.sql) each have five tables and five references. They exercise composite keys, quoted identifiers and warnings.
