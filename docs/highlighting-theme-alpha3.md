# MarkWriter 2.1.0-alpha3 implementation and acceptance

**Current correction:** application source `15f25d1` restores CSS/Swift/Makefile, adds Objective-C `m` and prevents automatic replacements in technical editing contexts. Read [feedback acceptance](alpha3-feedback-acceptance.md) and [its machine qualification](alpha3-feedback-qualification.json) for the 235-test/26-code-case native/package evidence and remaining limits. Core scope is toolbar theme consistency (#38), ordinary code highlighting (#40), recognizable packaged icon and valid macOS ad-hoc sealing (#39). View provides explicit Auto/Light/Dark choices synchronized with Settings. Alpha2 remains a completed immutable prerelease. Full PDF (#41), DBML (#33), SQL DDL (#42), PlantUML and other backlog are deferred. A PDF feasibility note is optional after core acceptance.

Markdown remains canonical. Highlighting uses decorations in CodeMirror and ProseMirror; toggles never alter language attributes, content, dirty state, history, selection, folds or independent font preferences. One persisted default-on preference controls toolbar, View, both editors, Preview and HTML export. Export captures the preference before asynchronous diagram work, uses a fixed readable light palette, and embeds all token CSS without scripts or network dependencies.

Exact original source bytes are required for view-only changes and source-editor Undo. Actual WYSIWYG edits use the existing Markdown serializer and can normalize whitespace; rendered Undo restores the document model, with the same serialized bytes and dirty state as an independently edited/undone copy without syntax toggles. Native acceptance checks that comparison, rather than claiming original-byte restoration for real rendered edits.

Native acceptance exposed source synchronization entering ProseMirror history: a rendered Undo could resurrect text already undone in CodeMirror. Synchronization now marks its replacement transaction `addToHistory=false` and closes the prior history group. A controlled-clock real-editor regression fails before this fix and passes afterward; the native model-restoration comparison remains a required gate.

One Windows installed run also reported atomic preference replacement access denial, while a same-tree run passed. The original cause is unproven. Windows now retries only replacement errors 5/32/33 using the same prepared temporary file, five attempts with 20/40/80/160 ms delays (300 ms scheduled per replacement, up to 600 ms across backup and current, plus filesystem/scheduling overhead). Other errors/platforms remain single-attempt. Permanent failure stays visible with backup/current context; no destination deletion, permission changes or non-atomic fallback. Deterministic Windows handle-lock tests must pass in CI.

Further native acceptance caught a wrapped-toolbar table picker opening off-screen at 800 px. The picker now measures its actual width, clamps horizontal placement to viewport margins and repositions on growth/resize; a grown 40×40 selection passes all 18 built-in-browser theme/mode/width combinations. A deferred-save regression also proved a late file-operation completion could close a newer menu; async commands now dismiss their own menu before starting work. Final review additionally identified stale async Cut/Paste completion across tabs or changed selections; captured owner/revision/engine/selection validation protects these operations. Final-source tests and native package acceptance below determine qualification.

The local highlight.js 11.11.1 / lowlight 3.3 grammar registry covers C, C++, C#, Objective-C, SQL, Bash, Zsh (Bash grammar), Rust, Python, Go, YAML, JSON, XML, JavaScript, TypeScript and Dockerfile. Recognized explicit fence names and common aliases win; metadata after the first word is not a language. Explicit plain/unknown/reserved diagram notations are not auto-detected. Unlabeled code is best effort: the highest relevance must be at least 5, lead the runner-up by 2 and by 25%; otherwise it stays plain.

Presentation work is capped at 4 Ki UTF-16 units per explicit block, 2 Ki per automatic block or line, 16 Ki / 64 blocks / 4 automatic blocks per document rebuild, 4096 token spans per block, and 128 cached results totaling at most 512 Ki key units. Oversized, uncertain and failed cases stay readable plain text; there is no source truncation or normalization. These are input/work-count limits, not a hard real-time lexer guarantee. Adversarial inspection found 16 Ki C++ repeated identifiers could take 720 ms cold even with short lines; the total block cap now rejects them before lexing (4 Ki equivalent measured44 ms). Cached unchanged blocks avoid repeated lexing during edits. All grammars/assets are bundled offline.

Official API references: [lowlight AST API](https://github.com/wooorm/lowlight#api), [highlight.js public API](https://highlightjs.readthedocs.io/en/latest/api.html). CodeMirror and ProseMirror public decoration/compartment contracts were inspected in the installed pinned declarations because their documentation sites returned HTTP 403 in this environment.
