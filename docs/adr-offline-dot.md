# Offline DOT trust boundary

6 November 2026 — alpha2 implementation; qualification in progress.

Canonical `dot` and `graphviz` fences remain Markdown. SVG is a disposable view and has block correspondence only. The opaque rendered editor node retains notation/source; unchanged mode/view changes never serialize it. Source editing/search/folds remain the editor's existing responsibilities.

The pinned runtime is `@viz-js/viz`3.31.0 / Graphviz16.1.0. Only the `dot` layout engine and SVG format are exposed. The runtime's WASM bytes are embedded in a separately loaded local worker bundle; there are no image files, external fonts, runtime downloads, installed Graphviz, subprocesses or hosted rendering. Text uses local platform fonts; exact font metrics may differ.

Trust boundaries: untrusted fence → lexical resource/attribute policy → worker/WASM → untrusted raw SVG → reconstructing static SVG allowlist → Preview/node/export. No raw Graphviz SVG enters the live DOM. Attribute assignments are tokenized, including quoted names and comments, then allowlisted. HTML labels, concatenated strings and all unlisted attributes are unsupported. In particular images, filesystem paths/includes, links/URLs, stylesheets, font paths, arbitrary engines and xdot backgrounds are excluded. Text labels can contain URL-looking text without creating links. The authoritative supported attribute list is `DOT_ATTRIBUTES` in `frontend/src/lib/dotSafety.ts`.

SVG reconstruction permits static geometry, groups, text/title/description only. It creates fresh SVG elements and copies only validated bounded numeric geometry, color, transform and text/font attributes. No event handlers, IDs/classes, style/CSS, href/xlink, resource nodes, scripts, foreignObject, animation or external namespace content survives. Anchors are unwrapped to safe children. Only the fixed upstream Graphviz SVG1.1 DTD is removed; other DTD/entity declarations fail. Limits:2MiB UTF-8 output,50000 visited elements,64 nesting levels and finite coordinates up to100000. These are intentional supported-subset limits.

One worker is active, with at most32 waiting jobs and64KiB UTF-8 source per job. Startup has5s; layout has2s from readiness. Every completion terminates the worker. Cancellation terminates active work or removes queued work immediately. Callers attach document/revision/generation ownership; stale callbacks cannot consume another job's response. View callers cancel on source changes, deactivate and unmount. Export retains its captured source owner through the existing I/O contract. There is no hard WASM heap limit: a2s kill budget limits time, not peak memory; large layouts may exhaust memory before it fires. Graphviz warnings are reported as recoverable errors rather than silently ignoring unsupported values. Errors retain source and render as escaped text, with retry by source edit.

Worker response CSP is `default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; connect-src 'none'; img-src 'none'; style-src 'none'; font-src 'none'; worker-src 'none'; object-src 'none'`. Only `/assets/dotWorker-*.js` receives this header through Tauri's resource response callback. The document keeps its existing policy and gains no WASM/general eval permission. The configured native window is built in setup so this callback applies to production assets. Vite dev/preview attach the corresponding worker header for browser qualification. Document meta CSP alone is insufficient evidence. Production response policy, offline rendering, timeout recovery and UI responsiveness require actual application qualification on all three target platforms.

References: [Viz API](https://viz-js.com/api/), [Graphviz attributes](https://graphviz.org/doc/info/attrs.html), [Tauri CSP](https://v2.tauri.app/security/csp/), [MDN worker policy](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers#content_security_policy). Installed Tauri2.8.4 `WebviewWindowBuilder::on_web_resource_request` and installed Viz declarations are the exact version API references.
